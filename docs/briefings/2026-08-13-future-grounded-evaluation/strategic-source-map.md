# 战略材料与原始聊天的对应关系

本文用于审计新版战略材料的来源，不进入主汇报。原始记录是 `raw/chatgpt-share-transcript.md` 和 `raw/chatgpt-share-messages.json` 中的 11 轮可见问答。

## 采用原则

- 第 9 轮决定材料讲什么：landscape、位置、问题、相关工作、工作包、预计效果和边界。
- 第 10 轮决定材料怎么讲：先例子，后术语；中文优先；公式最多两条；用同一个对照实验贯穿全文。
- 第 11 轮决定哪些话不能讲过头：RSI 不是立项前提，Generator 不能自证，不做通用项目优化，里程碑与愿景分开。
- 第 1 至 8 轮用于解释最终结论为何形成；其中被后续推翻的方向不进入主线。

## 分节来源

| 新版材料内容 | 主要聊天轮次 | 保留的结论 |
| --- | --- | --- |
| 开场：改进方案越来越便宜，可靠选择成为瓶颈 | 7、10、11 | benchmark 从测量工具变成优化目标；候选越多，评测误差越容易被搜索到 |
| Landscape | 2、8、9 | 公共 benchmark、未来导向任务、交互式评测、self-improving Agent 和 evaluator evolution 分别补了不同部分 |
| Barcarolle 的位置 | 1、2、7、9 | Barcarolle 是面向未来真实工作的评测器，不是公共排行榜、实验运行平台或改进方案生成器 |
| 核心问题 | 1、7、9、10 | 固定 Agent 上测得准，不代表反复优化后仍能选对版本；Generator 的具体成题方式也可能决定结论 |
| 相关工作及其缺口 | 8、9 | SWE-bench、SWE-Future、SWE-Interact、SWE-Together、DGM/ADAS、RQGM 各自解决一段，没有闭合“连续优化后仍与未来真实工作对账” |
| Generator 的三层检查 | 9、10、11 | 需求方向是否对、具体成题是否走偏、不同 Agent 的相对表现是否能被后来真实任务验证 |
| Selector 与暴露管理 | 1、7、8、9 | 从预测平均分升级为保留版本差异、排序和最终选择；记录评测暴露并按阶段刷新 |
| 核心对照实验 | 7、8、9、10、11 | 同一初始 Agent、同一自动优化器、同样预算，只换评测器；最后一次性打开真实后续任务 |
| 预计效果 | 1、7、9、10 | 少选错版本、让评测提升更多转化为真实提升、延长可靠优化轮数、同等可靠度下降低评测成本 |
| 可行性与路线 | 8、10、11 | 先做固定候选压力测试，再补 Generator/Selector，最后进入闭环；不需要先造通用 RSI 系统 |
| 风险与边界 | 5、7、9、10、11 | 不预测未来本身，不做通用项目优化，不让 Generator 自证，不把训练挑战题当真实未来代理，第一阶段保留 pass/fail |

## 两个贯穿全文的例子

1. 第 7、10 轮的示意数字：评测分数从 60、70、80、90 持续上涨，未来真实表现却是 60、67、70、68。它只解释机制，不是实验结果。
2. 第 9、10 轮的 serialization 例子：即使预测对未来需求方向，Generator 仍要决定具体类型、API、边界条件和测试；这些选择可能改变 Agent 排名。

## 被后续撤回或降级的方向

| 早期方向 | 最终处理 | 来源 |
| --- | --- | --- |
| benchmark 直接告诉工程师或 Agent 应该怎样优化项目 | 不进入主线；失败归因不等于改动的因果效果 | 第 3 至 5 轮 |
| 生成一个 future workload 来评价任意项目是否“变好” | 撤回；项目改动会改变未来 workload，本身也没有统一二元结果 | 第 4、5 轮 |
| Diagnostic interventions 作为持续优化空间 | 降级为校准用的已知改动；若候选只有几种，直接做 ablation | 第 6、7 轮 |
| Barcarolle 提供类似梯度的改进方向 | 改为提供选择压力；外部 Proposer 负责产生候选 | 第 7 轮 |
| Generator 单独具备 counter-Goodhart 性质 | 撤回；这是 Generator、Selector、暴露协议和真实未来审计共同承担的系统性质 | 第 9 轮 |
| 一开始定义多维项目价值 | 后置；第一阶段继续用真实 coding task 的 pass/fail | 第 5、6、10、11 轮 |
| RSI 是项目成立前提 | 撤回；当前版本选择需求已经成立，RSI 只放大问题 | 第 10、11 轮 |

## 写作检查

- 删除某句话后，如果读者没有少掉事实、判断、原因、动作或边界，就删除。
- 抽象术语必须紧跟例子或普通中文解释。
- 主文不放仓库实验数字、算法名、文件路径、审计过程或完整数学符号。
- 所有示意数字和目标曲线必须标为示意或待验证。
- “后来真实发生的工作”始终是最终对账依据，不能由 Generator、Selector 或优化器自行定义。
