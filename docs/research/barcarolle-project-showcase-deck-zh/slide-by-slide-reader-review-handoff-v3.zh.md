# Barcarolle 项目展示 Deck V3 逐页读者反馈 Handoff

状态：V3 修订输入，2026-06-02。

用途：记录用户对 V2 中文项目展示 deck 的逐页原始评审意见，供执行
agent 在修订 V3 时做内部审查。本文不是 reader-facing material，不能把
本文中的过程性句子直接搬进 PPT。

## Overall Intent

V2 已经解决了一部分重复页问题，但仍然偏内部过程材料。V3 需要以读者
问题组织叙事：

- 这个问题是否真实存在？
- Barcarolle 的方法怎样回答这个问题？
- 现在已有证据说明这条路值得继续走吗？
- 算法和验证路线怎样演进？
- Agent License 和 Agent Tuning 两个产品化方向怎样使用这套证据层？

V3 不能只修图、换配色或删几个术语。它需要把页面结构、相关工作、证据
选择和视觉对象一起调整。

## Required Internal Review Questions

执行 agent 完成 V3 后，必须以读者身份回答：

1. 第一页是否解释了 ACUT，并且没有出现“被测 ACUT”？
2. 问题页是否把“通用 benchmark 分数”和“目标仓库未来工作表现”之间的
   缺口讲具体？
3. 相关工作页是否写全名称，并用直观语言说明每类工作留下的问题？
4. 研究目标页是否让非项目内部读者理解 predictive validity 和 MAE？
5. 方法页是否只保留必要术语，并去掉意义不明的底部矩形和过程文本？
6. 执行边界和算法环境页是否改成中文、可读、低术语密度？
7. 当前证据是否回答“问题真实、方法可推进、路线可演进”，而不是堆
   过程数据？
8. 研究路线是否把核心算法演进放回中心，而不是把基础协议动作当成
   未来研究重点？
9. Agent License 和 Agent Tuning 页是否用正面表述说明用途，没有
   “但不负责……”式边界声明？
10. 所有图是否没有孤立矩形、错误连接、不可解释标签或明显生成痕迹？

## Text That Must Not Leak Into The Deck

以下内容可以在 runbook、handoff、QA 报告中出现，但不能出现在 reader-facing
PPT 文本中：

- `runbook`
- `handoff`
- `M1` / `M2` / `M3` / `M4` / `M5` / `M6`
- `V1` / `V2` / `V3`，除非在文件名或内部审计报告中
- `过程性文本`
- `这不是……而是……`
- `不是……而是……`
- `是……不是……`
- `但不负责`
- `不接管`
- `读者不关心`
- `AI 写`
- `我们刚才讨论`

## Expected V3 Direction

推荐 V3 压缩到 `11` 或 `12` 页：

1. 项目定位：解释 ACUT 和三方关系。
2. 问题与代价：合并原 Slides 2/3。
3. 相关工作与缺口：写全名称，补 SWE-Bench++。
4. 研究目标：LaTeX 公式和 MAE 的直观解释。
5. 方法：唯一完整 compiler workflow，减少术语。
6. 执行边界：中文边界图。
7. 算法问题：selection/support/fallback 如何影响估计。
8. 当前证据：问题真实、基础设施可行、random control 和 MAE 牵引信号。
9. 研究路线：核心算法演进和 future holdout / rolling-origin 验证。
10. Agent License：治理证据层。
11. Agent Tuning：受保护的反馈回路。

如果执行 agent 保留单独限制页，必须证明它回答了一个读者问题，而不是
保留内部诊断材料。
